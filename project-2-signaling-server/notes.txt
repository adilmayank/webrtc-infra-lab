- "You can explain why signaling isn't part of the WebRTC spec itself" -> Signalling is considered as a separate mechanism that can happen via an independent channel. Since in order to media packets to flow, both peers must know firsthand where to send the packets. Both peers have to send their own ICE candidates that then can be nominated to be a common channel for packets to flow back and forth. That discovery is something an independent channel has to help with. It can be done via a websocket connection or via an http api call. Websocket connection has become an industry standard because it is low latency birectional communication channel that can be used for sending/receiving other types of messages apart from webrtc ones.
